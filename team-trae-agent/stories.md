# User Stories - Web Terminal Time Machine

## Story 1: 基础 Web 界面搭建
- **点数**: 1
- **说明**: 创建一个极简的单页 HTML/JS 应用，打开浏览器直接看到黑乎乎的终端窗口，无注册/登录流程

### 验收标准
- [ ] AC1: 页面加载后直接显示终端界面，无任何登录/注册入口
- [ ] AC2: 终端界面采用深色主题（黑色背景）
- [ ] AC3: 页面可在浏览器中直接打开（file:// 或本地服务器）

---

## Story 2: 伪终端模拟 (Mock Terminal)
- **点数**: 3
- **说明**: 使用 xterm.js 实现伪终端，支持基本 echo 和模拟命令

### 验收标准
- [ ] AC1: 使用 xterm.js 库渲染终端
- [ ] AC2: 实现基本 echo 功能：用户输入什么显示什么
- [ ] AC3: 实现 `help` 命令：显示可用命令列表
- [ ] AC4: 实现 `ls` 命令：返回模拟的目录列表（如 `file1.txt  file2.js  src/`）
- [ ] AC5: 输入未定义命令时显示错误信息

---

## Story 3: 录制功能 (Record)
- **点数**: 3
- **说明**: 记录终端的输入按键和时间戳，支持开始/停止录制

### 验收标准
- [ ] AC1: 界面显示 "Record" 按钮
- [ ] AC2: 点击 Record 按钮开始录制，按钮变为 "Recording..." 状态
- [ ] AC3: 录制过程中记录每个按键的内容和时间戳（相对起始时间的毫秒数）
- [ ] AC4: 再次点击 Record 按钮停止录制
- [ ] AC5: 录制数据存储在内存中（数组形式）

---

## Story 4: 回放功能 (Replay)
- **点数**: 3
- **说明**: 按原速度重现录制期间的所有输入操作

### 验收标准
- [ ] AC1: 界面显示 "Replay" 按钮
- [ ] AC2: 点击 Replay 按钮清空终端屏幕
- [ ] AC3: Replay 按录制时的原始时间间隔重放每个按键
- [ ] AC4: Replay 过程中显示 "Replaying..." 状态
- [ ] AC5: Replay 完成后自动显示录制时的命令输出结果

---

## Story 5: 集成测试 - 单元测试
- **点数**: 2
- **说明**: 为核心功能编写单元测试

### 验收标准
- [ ] AC1: 为命令解析逻辑编写单元测试（覆盖 help, ls, echo, 未知命令）
- [ ] AC2: 为录制功能的时间戳记录逻辑编写单元测试
- [ ] AC3: 为回放功能的时间间隔计算逻辑编写单元测试
- [ ] AC4: 所有单元测试通过后才能进入 e2e 测试阶段

---

## Story 6: 集成测试 - E2E 测试 (Playwright)
- **点数**: 2
- **说明**: 使用 Playwright 进行端到端测试验证完整用户流程

### 验收标准
- [ ] AC1: 测试页面加载后直接显示终端界面（无登录）
- [ ] AC2: 测试终端 echo 功能正常
- [ ] AC3: 测试 `ls` 命令返回模拟目录列表
- [ ] AC4: 测试完整的 Record -> Replay 流程
- [ ] AC5: 测试 Replay 后终端显示的内容与录制时一致

---

## 总点数: 14

## 开发纪律
1. **遵循 TDD**: 先写测试，再写实现代码
2. **小步前进**: 每个 Story 完成后才能开始下一个
3. **单元测试优先**: 在单元测试完成前，禁止进行 e2e 测试
4. **E2E 使用 Playwright**: 使用 Playwright 进行端到端测试验证
